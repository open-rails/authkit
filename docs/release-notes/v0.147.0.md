# v0.147.0: the #399 hard cut

Every host breaks. There are no aliases or shims; this table is the migration.

- One host type, `*authkit.Auth`, from the root package. Shared types live in
  `iam`; the engine is `internal/engine`, the HTTP layer `internal/httpapi`.
- Every mutation takes an `iam.Actor` right after `ctx`; reads take none. The
  zero actor is refused. Host code acts as `iam.OperatorActor()`; requests act
  as the actor `verify.ActorFromClaims` derives. See [roles](../roles.md).
- `authkit.New(ctx, cfg, deps)` takes a context: it creates the root group and
  reconciles the role catalog at boot.
- `Config.HTTP` is an `authkit.HTTPConfig` value; the zero value is headless.

- A one-time link never answers `invalid_token`: a spent, expired or unknown
  verification, reset or passwordless link is `400 invalid_link`, a wrong code
  `401 invalid_code`. `invalid_token` is only for bearer and refresh tokens.
- A replayed SIWS message answers `challenge_not_found`.
- Deleted, nothing emits them: `email_unchanged`, `failed_to_request_phone_change`,
  `phone_unchanged`, `session_creation_failed`, `user_role_not_found`,
  `failed_to_update_preferred_language`, `not_group_member`, `token_revoked`,
  `email_not_verified`, `preferred_language_lookup_failed`, `failed_to_unban`.
- auth-ui: regenerate against `error-codes.ts`. `STALE_BEARER` is
  `token_expired`, `invalid_token`, `unauthenticated`, `unknown_kid`.

Other wire changes:

- API-key JSON `key_id` → `lookup_id`. `GET …/api-keys`, `…/invites/links` and
  `…/remote-applications` return `{object:"list", data, next_cursor}` and take
  `?cursor=&limit=`.
- Delegated tokens are refused on AuthKit's own management routes.
- Admin account routes (ban, unban, delete, restore, session revoke, root
  roles) authorize in the engine and accept user actors only.
- New `DELETE {api}/{persona}/{slug}` soft-deletes a group (`<p>:self:delete`).
- Built-in permission names changed as in the table above.
- `GET /me` drops `user_aliases`, `solana_address` and `discord_username`; read
  `solana_linked_account`.
- A service JWT's authority is its `permissions` claim; `scope` grants nothing.
- The `plan` claim is no longer read as `user_tier`.
- SIWS takes its domain from configuration only, never Origin or Host.

## Behavior

- Machine actors (API keys, applications, delegated tokens) never issue API
  keys or invites. A user-issued credential dies with its creator's authority:
  demotion, ban, deletion or a role-catalog change revokes it, and every use
  re-checks the creator.
- `New` stores a role-catalog fingerprint; when it changes, `New` re-checks
  every credential. A catalog role shadowing a stored custom role fails `New`.
- MFA follows permissions: API keys and applications never hold an MFA role.
- Checks are live for every actor. An unregistered permission makes `Can`
  return `iam.ErrUnknownPermission` and `RequirePermission` panic at build.
- Adding a member by email never binds an account; it invites (see Security).
  Bootstrap and `EnsureUserRole` never adopt an account by username, alias or
  unverified contact.
- `PurgeUsers` ends the recovery window by moving `purge_at` forward;
  `deleted_at` keeps the real deletion time.

## Migrations

- `0005_drop_group_containment`: drops `permission_groups.parent_id`,
  `group_persona_parents` and the containment trigger.
- `0006_credential_issuers`: `invited_by` nullable (operator invites);
  `api_keys.created_by` cascades on delete and existing creator-less keys are
  revoked; issuer indexes; `role_catalog_state`.
- `0007_custom_role_mfa_and_early_purge`: drops `group_custom_roles.requires_mfa`;
  the purge CHECK becomes `deleted_at <= purge_at <= deleted_at + 720h`.
- `0008_security_fixes`: `refresh_sessions.mfa_authenticated_at` (backfilled
  from `created_at` for MFA sessions), `user_device_keys.mfa_proven_at`,
  `remote_applications.registered_by` (earlier group registrations have none
  and confer nothing until re-registered), `account_deletions.deleted_by`.

## Security

Escalation audit 2 (N1–N10) and its leftovers:

- `POST /step-up/password` and provider step-up answer `step_up_required`
  (`mfa_required`) for an account with a second factor; its tokens' `auth_time`
  is the session's last second-factor proof, so a password re-auth never clears
  a sensitive gate. AuthKit's sensitive routes read live MFA state (N1).
- Device keys pass the session MFA gate: a key counts as a second factor only
  when enrolled with `code_2fa`; others are refused (`2fa_required`,
  `2fa_enrollment_required`) once the account needs MFA. A password change or
  reset revokes every other device key (N2).
- Machine actors cannot register remote applications. A group registration's
  registrar bounds its roles, and the credential sweep drops them when the
  registrar is demoted, banned or deleted (N3).
- The first proof of an address also revokes the squatter's invite links and
  account invitations and orphans its applications (N4).
- Signing in restores only a self-deleted account; staff deletions answer
  `account_disabled` and come back through `RestoreUsers` (N5).
- Self rules compare canonical (lower-case) ids (N6).
- `Verifier.Verify` refuses 2FA-enrollment tokens (and, under Required 2FA,
  unenrolled user tokens); `verify.ActorFromClaims` yields no actor for them (N7).
- The role-catalog fingerprint covers `RequireMFA` and the 2FA mode: keys and
  application roles that come to need MFA are revoked at boot and confer
  nothing at use (N8).
- Adding a member by email always answers `202` with an invitation, accepted by
  registering or by the account that verified the address at
  `POST /invites/redeem`; a failed verify link is always `400 invalid_link` (N9).
- A contact change never leaves an MFA-enrolled account unproven (N10).
- Bootstrap refuses MFA-required root roles for applications; `CreateGroup`
  refuses a banned actor's live token; `MintAPIKey` refuses a persona without
  `APIKeys`, for the operator too.

## Removed

The containment tree (`Parent`, parent chains), `ReservedEscalationRole`,
`HTTPConfig.Documents`, `PerProcessRateLimits`, token role claims, the `plan`
and service-JWT `scope` fallbacks, SIWS Origin/Host domain fallback, the `/me`
duplicate fields, `GroupDirectory`, `WithResolvedGroup`, the compatibility
tooling (`compatibility/`, apidiff), and the public `dpop`, `password`,
`ratelimit` and `oidckit` packages.
