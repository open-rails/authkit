AuthKit's critical suite exercises the public embedded Go client, the mounted HTTP server, real Gin/Fiber adapters, PostgreSQL, Redis, and River. Email/SMS delivery is captured at the external sender boundary. External issuer failures use local TLS servers; storage outages cut a real owned TCP connection. No AuthKit service or authorization result is mocked.

The four J36 configured-group cases exercise `EnsureGroups` with a one-connection
caller pool and no runtime configuration, preserving memberships and create
events on replay, refusing invalid/conflicting/deleted groups, and converging
concurrent migrations and cancelled-call retries.

`scenarios.json` names the 219 Go scenarios. The separate `auth-ui` suite requires nine J29 scenario IDs, exercised with the selected client methods in 23 browser/client cases; its result checker also requires the exact set of 23 executable case IDs. The required result checker rejects failures, skips, missing scenario passes, and duplicate scenario IDs; a passing nested branch cannot qualify a failed parent scenario.

Run the backend suite with `scripts/check.sh workflows`, or select a journey locally with `go test -run 'TestCriticalSessions' -v ./critical`. Set `AUTHKIT_TEST_DATABASE_URL`, `AUTHKIT_TEST_REDIS_URL` and `AUTHKIT_TEST_PGBOUNCER_URL` (PgBouncer in transaction mode in front of that database) to disposable services. Each journey owns a PostgreSQL schema and runs in parallel with the others, except the few marked Serial, which change process-wide state, share Redis keys or time themselves; no test skips because a service is missing. `scripts/check.sh contracts` retains compiler/vet, sqlc generation/validation, and released migration checks.

The admission matrix (AK-J31-C01) probes every mounted route by the tier `Client.Routes()` declares, with missing, malformed, expired, revoked and unprivileged credentials; `api/openapi.json` pins each route's tier. SCIM routes authenticate their own credential and are probed too, all but the directory's discovery documents. Optional features are mounted for their refusal probes. Successful state transitions belong to the named journeys and shipped TypeScript flows: denial probes alone do not qualify a feature's full functionality. AK-J31-C06 limits every rate bucket the HTTP surface declares at its own boundary: each route bucket through a mounted route, each in-handler bucket through the request it counts; a bucket with neither fails.

The suite prioritizes credentials, permissions, tenant boundaries, recovery, token profiles, retained events, and account deletion. Sign-in by device key (AK-J10), passkey (AK-J42), OIDC provider (AK-J45, against `internal/testidp`, an OpenID Provider on a local TLS server issuing signed ID tokens) and Solana wallet (AK-J46), and the authorization server's code, refresh and client-credentials grants (AK-J44), each have their success path and the refusals that guard it. OAuth federation/consent, directory synchronization, and presentation coverage remain expansion work. Runtime cases inside a journey are distinct from the scenario count; neither count claims every possible input or schedule.

Time is controlled at existing clock and external timestamp boundaries. The deletion cutoff case pauses the actual database scan through a pgx driver hook, then ages its three imported fixture timestamps to one microsecond before, exactly at, and one microsecond after the cutoff obtained by the real worker. The hook changes no query or result; an exclusive-cutoff mutation must fail. It holds the next pass too, which comes for the account past the cutoff at its own deadline. The provisioning cases push to an in-process SCIM service provider at the external boundary, which records what it receives and when and can answer 503; an idle target's cases wait for River to run a scheduled no-op run, then find no run queued; the listener case cuts the listener's real connection with `pg_terminate_backend`. The transaction-pooler journey (AK-J47) runs AuthKit through a real PgBouncer in transaction mode that keeps no prepared statements (`AUTHKIT_TEST_PGBOUNCER_URL`), with its direct sessions through a TCP link the test stalls to play a silent network partition. The deletion-instant case imports deletions whose window ends seconds later. Direct fixture updates only age a specific owned expiration/retention timestamp; assertions read public APIs. The cleanup convergence case uses small independently expired cohorts, not a maximum-batch load benchmark. Stateless token verification intentionally differs from live session and permission checks. The sender-health cases drive a sender whose health checks wait for the test's answer, with a one-second check interval and a 10 ms re-check: a check that starts within half the interval is a re-check, and one that starts later is the periodic check. No case waits on a real provider or the five-minute schedule. The refresh-reuse case moves the engine clock past the 30 s grace window (`internal/testclock`) instead of sleeping.

The published `authtest`, `auth/authtest`, and `userinfo/userinfotest` packages remain supported for downstream consumers. Their existing helpers are not counted as new AuthKit behavioral coverage. Old private harnesses with no remaining imports were removed.
